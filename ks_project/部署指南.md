# 快手金币助手 - 完整部署指南

本指南适用于 CentOS Stream 9 + 雷电模拟器 9 (LDPlayer 9) 环境。

---

## 架构概览

```
Windows 宿主机                    CentOS 虚拟机
+-------------------+            +---------------------------+
| 雷电模拟器 9       |  ADB连接   | Python签名服务 (端口5000)  |
| - 快手极速版       | <--------> | Node.js Web控制台 (端口3000)|
| - frida-server    |            | ks_script.js 任务脚本      |
+-------------------+            +---------------------------+
```

- **Windows**：运行雷电模拟器，提供 Android 环境（自带 Root）
- **CentOS**：运行签名服务、Web 控制台、任务脚本
- **连接方式**：CentOS 通过 ADB 网络调试连接 Windows 上的雷电模拟器

## 1. CentOS 基础环境

```bash
# 更新系统
sudo dnf update -y

# 安装 Node.js (LTS)
curl -fsSL https://rpm.nodesource.com/setup_lts.x | sudo bash -
sudo dnf install -y nodejs

# 安装 Python 3 和 pip
sudo dnf install -y python3 python3-pip

# 安装 ADB
wget https://dl.google.com/android/repository/platform-tools-latest-linux.zip
sudo dnf install -y unzip
unzip platform-tools-latest-linux.zip
echo 'export PATH=$PATH:~/platform-tools' >> ~/.bashrc
source ~/.bashrc

# 安装 Git
sudo dnf install -y git

# 验证
node -v && python3 --version && adb version
```

## 4. Frida 环境部署（重点）

### 4.1 版本要求

**Python frida 版本和 frida-server 版本必须完全一致。**

```bash
# 安装 Python frida（会自动安装对应版本）
pip3 install frida frida-tools flask

# 查看安装的版本
python3 -c "import frida; print(frida.__version__)"
# 例如输出: 17.6.0
```

### 4.2 下载 frida-server

根据上一步输出的版本号下载 **完全相同版本** 的 frida-server。

**架构选择**：雷电模拟器 9 是 x86_64 架构。

```bash
# 确认模拟器架构
adb shell getprop ro.product.cpu.abi
# 输出 x86_64 -> 使用 frida-server-android-x86_64
# 输出 arm64-v8a -> 使用 frida-server-android-arm64（极少见）

# 下载（以 17.6.0 为例，替换为你的实际版本）
wget https://github.com/frida/frida/releases/download/17.6.0/frida-server-17.6.0-android-x86_64.xz
xz -d frida-server-17.6.0-android-x86_64.xz
```

### 4.3 推送并启动

```bash
# 推送到模拟器
adb push frida-server-17.6.0-android-x86_64 /data/local/tmp/frida-server

# 设置权限
adb shell "su -c 'chmod 755 /data/local/tmp/frida-server'"

# 启动 frida-server（监听所有接口）
adb shell "su -c '/data/local/tmp/frida-server -l 0.0.0.0:27042 &'"

# 设置端口转发
adb forward tcp:27042 tcp:27042
```

### 4.4 Frida 17.x Java Bridge（关键）

**Frida 17.0.0 起有一个重大变更**：Java/ObjC/Swift bridge 不再自动打包到 GumJS 运行时中。

这意味着：
- 使用 `frida -U` CLI 工具时，Java 对象仍然可用（CLI 自动处理）
- 但通过 Python API（`session.create_script()`）加载的脚本中，`Java` 对象是 `undefined`

**本项目已处理此问题**：
- `ks.js` 使用 `import Java from "frida-java-bridge"` 显式导入
- `ksapi.py` 使用 `frida.Compiler().build()` 编译脚本（将 bridge 打包）
- `scripts/package.json` 声明了 `frida-java-bridge` npm 依赖

因此你需要在 scripts 目录安装 npm 依赖：

```bash
cd ks_project/scripts
npm install
```

**如果不想使用 Frida 17.x**，可以降级到 16.x（不推荐）：
```bash
pip3 install frida==16.7.19 frida-tools==12.5.9
# 同时下载 frida-server-16.7.19-android-x86_64 替换模拟器中的
```

### 4.5 验证 Frida

```bash
# 验证 frida-server 是否运行
adb shell "ps | grep frida"

# 验证 Java bridge 是否可用（需要快手进程存在）
frida -U -n "快手极速版" -q --eval 'console.log("Java available:", Java.available)'
# 应输出: Java available: true
```

## 6. 抓包获取参数

你需要从快手极速版的网络请求中获取以下 **4 个参数**：

| 参数 | 说明 | 在 Cookie 中的字段名 |
|------|------|---------------------|
| `kuaishou.api_st` | 登录凭证（最重要） | `kuaishou.api_st=Cg9r...` |
| `userId` | 用户 ID | `userId=1788284763` 或 `ud=1788284763` |
| `egid` | 设备指纹 ID | `egid=DFP7AE5F...` |
| `did` | 设备 ID | `did=ANDROID_f4b7...` |

**注意：不需要 salt 值。** salt 是签名算法中的固定常量，已硬编码在脚本中。

### 抓包方法

1. 在模拟器中安装 **HttpCanary**（需要 Root 权限，雷电已开启）
2. 启动 HttpCanary，开始抓包
3. 打开快手极速版，登录账号，刷几个视频或进入任务中心
4. 停止抓包，筛选域名 `api.e.kuaishou.com` 或 `api.kuaishou.com`
5. 查看任意请求的 Cookie 头，提取上述 4 个字段

### 快捷方式

新版前端支持 **粘贴完整 Cookie 自动提取**：
1. 在 HttpCanary 中复制完整的 Cookie 字符串
2. 粘贴到 Web 控制台的 "粘贴完整 Cookie" 文本框
3. 点击 "自动提取" 按钮，系统会自动填充 4 个字段

## 7. 启动服务

需要开启 3 个终端（或使用 tmux/screen/PM2）：

### 终端 1：启动 frida-server（如果尚未启动）

```bash
adb shell "su -c '/data/local/tmp/frida-server -l 0.0.0.0:27042 &'"
adb forward tcp:27042 tcp:27042
```

### 终端 2：启动 Python 签名服务

```bash
cd ks_project/scripts
python3 ksapi.py
# 输出: Running on http://0.0.0.0:5000
```

启动后应看到：
- `Java.available: true` - Java bridge 正常
- `RPC ping: ok` - RPC 通信正常

### 终端 3：启动 Web 控制台

```bash
cd ks_project
node server.js
# 输出: Web console running at http://localhost:3000
```

### 使用 PM2 管理（推荐）

```bash
sudo npm install -g pm2

cd ks_project
pm2 start server.js --name "ks-web"
pm2 start "python3 scripts/ksapi.py" --name "ks-api" --cwd scripts

pm2 save
pm2 startup
```

## 8. 使用 Web 控制台

1. 在 Windows 浏览器访问 `http://<CentOS_IP>:3000`

## 常见问题

### Q: 防火墙拦截？
```bash
# 临时关闭防火墙（测试环境）
sudo systemctl stop firewalld

# 或只开放端口
sudo firewall-cmd --add-port=3000/tcp --permanent
sudo firewall-cmd --add-port=5000/tcp --permanent
sudo firewall-cmd --reload
```

### Q: 签名服务报 "Java 不可用"？
1. 确认 frida-server 版本与 Python frida 版本完全一致
2. 确认 `scripts/node_modules/frida-java-bridge` 目录存在（运行 `cd scripts && npm install`）
3. 清理旧的 frida 进程：`adb shell "su -c 'pkill -f frida'"`，然后重新启动

### Q: API 返回 "签名验证失败"？
1. 检查 `kuaishou.api_st` 是否过期（通常几小时到一天会过期，需要重新抓包）
2. 确认 `userId`、`egid`、`did` 填写正确
3. 查看终端日志中 `[签名]` 开头的输出，确认 sig、__NS_sig3、__NStokensig 都有值

### Q: 快手自动关闭？
这是正常现象。签名服务使用 Frida 的 spawn 模式会重启快手进程来注入脚本。脚本只需要快手进程在后台存在，不需要你手动操作 UI。

### Q: 即使没打开快手也显示进程存在？
Android 系统会保留后台进程（如 `:messagesdk`、`:push_v3`），这是正常行为。签名服务的 spawn 模式会在需要时自动启动主进程。

### Q: ADB 连接断开？
```bash
adb kill-server
adb start-server
adb connect <Windows_IP>:5555
adb forward tcp:27042 tcp:27042
```

### Q: api_st 多久过期？
`kuaishou.api_st` 通常在几小时到一天内过期。过期后需要重新打开快手、重新抓包获取新的 api_st。
